# P04 wave 1 — output-overflow termination decision

Status: owner approved the pinned-helper direction and bounded adapter-test debug on 2026-11-04; implementation and verification remain pending. The runner must terminate its process group promptly on output overflow or I/O failure, but Rust's safe standard library exposes child termination rather than process-group signalling. Killing the GNU `timeout` child alone can leave Git and helpers running. The project policy prohibits unsafe code. The runner remains fail-closed until the proposed controls are proven.

Proposed direction: review and explicitly pin `/usr/bin/kill` as an additional application-owned helper, validate its identity and behavior alongside Git and GNU `timeout`, and use argument arrays (never a shell) to signal only the process group created for the current invocation. Specify how to keep the group identity valid until signalling is complete, how TERM/KILL escalation, reaping, output drains and errors interact, and what happens if the helper fails or the child exits concurrently. Do not claim the approach is safe until those details and platform races are resolved. Local tests must include overflow and I/O failure, simultaneous output floods, child and grandchild termination with potency controls, helper failure, already-exited process handling, and no signalling of unrelated groups. Descendants that create a new session and same-user interference remain limitations.

Alternative: a reviewed safe signal API through a dependency would need separate approval and associated offline dependency/lock checks. No network or installs are authorized. If the approved helper direction cannot establish the required boundary, retain fail-closed behavior and revisit the runner design.
