# P04-T01 Git safety annex — approved design baseline

Scope: design baseline approved in `planning/P04-T01-request.md` §10; no P04 control below is verified by this document. References below to proposals or pending acceptance preserve the pre-approval design history. P00-T04 D01 passed 36 cases and one observation with Git 2.53.0 on one host using synthetic local transport; acceptance is limited to that procedure and fixtures. Real HTTPS/SSH, network credential-helper use, local includes/rewrites, SSH configuration, macros and other limitations in its record remain unproven. All P04 tests below are pending.

## Runner, isolation and credentials

Use pinned absolute `/usr/bin/git`, verify its exact parsed version is 2.53.x, and absolute pinned GNU `timeout`; fail closed if unavailable or malformed. Spawn argument vectors, never a shell, with explicit trusted cwd, no inherited or interactive stdin (null except for explicitly bounded app-owned binary input to `check-attr`), bounded concurrent stdout/stderr draining, wall time and byte/count/path limits. Proposed per-command caps: 8 MiB stdout, 64 KiB stderr, 100,000 paths, 4,096 bytes per path, 8 MiB aggregate stdin and 64 helpers of at most 4,096 bytes each; operation timeout 120 seconds, termination grace 2 seconds and version probe timeout 5 seconds; tighter caps may be used if fixed in the request. Count raw bytes before allocation and fail on overflow; stdout and stderr are drained concurrently to EOF, then checked for complete framing and exit status. On overflow, malformed output, timeout, signal or failed exit, abort and discard captured output. Do not interpolate a ref, path, URL or helper into an option. Operation commands use the P03 Git child environment from an empty environment, with only E3's explicit inherited `SSH_AUTH_SOCK` exception after name/value secret checks. The separately specified fixed app-authored `GIT_SSH_COMMAND` is an application-provided setting, never an inherited host value; GitEnv permits only the exact trusted policy below. Do not inherit `GIT_*`, `SSH_*` otherwise, proxies, askpass or trace variables. Agent socket is sensitive metadata: validate an absolute NUL-free socket path, do not log it; no assertion that its contents are secret-free or that the agent is trustworthy. E3 requires a narrowly scoped change to P03's deny rule before implementation.

All Git calls use a common argument prefix (each item separate): `-c core.hooksPath=/dev/null -c core.fsmonitor=false -c protocol.allow=never -c protocol.https.allow=always -c protocol.ssh.allow=always -c submodule.recurse=false`. Add `-c credential.helper=` followed by ordered explicitly selected `-c credential.helper=<value>` only to network operations. Do not accept Git output, repo configuration, or input as additional `-c` arguments, except the bounded, explicitly selected global helper values extracted under E3 below. Disable prompts; no interactive credential or host-key fallback. Production rejects local/file/ext transports. The E5 fixture-only file transport must be compile-time isolated and absent from release artifacts, including feature-unification paths; prove this rather than assuming a dev dependency is sufficient.

E3 extraction: in a private app-owned non-repository cwd, use a separate cleared environment with real HOME solely to read the user's global file; disable system config and explicitly select the intended global file. Invoke `git config --global --no-includes --null --get-all credential.helper` as an argv array, with no local config, hooks or helper invocation. Treat exit 1 with empty output as no helper; other failures, truncation, invalid NUL framing, NUL in a value, excessive count/size or unreadable/malformed config abort. Preserve ordering and empty reset semantics, never print/store helper values. Extracting values does not execute them; network use deliberately can execute the user's configured helper, which is trusted user code and can access user resources. Helpers with shell syntax are executable by Git even though the application launches no shell: this is an explicit E3 trust boundary, not a sandbox. Refuse ambiguous environment-dependent helper behavior; no repository helper or URL-scoped credential settings. Excluding includes may change the user's effective helper list; the conservative direct-file policy preserves only direct helper entries, and included or URL-scoped helper configuration is unsupported. Do not claim full preservation of the user's effective Git configuration. No global config should be read during normal operations.

SSH: app HOME alone does not prove isolation of OpenSSH config/keys because OpenSSH can resolve passwd home. Propose an app-authored, fixed `GIT_SSH_COMMAND` value selecting `/usr/bin/ssh -F <app-owned-config> -o BatchMode=yes -o StrictHostKeyChecking=yes`, not an inherited host variable; the config path must be trusted and shell-safe because Git interprets this value as a command. Its app-owned config specifies `IdentityFile none`, `IdentitiesOnly no`, an explicit approved `IdentityAgent` socket or the approved `SSH_AUTH_SOCK`, explicit trusted `UserKnownHostsFile`, `GlobalKnownHostsFile /dev/null`, `ProxyCommand none`, `ProxyJump none`, `PermitLocalCommand no`, `ForwardAgent no`, `BatchMode yes` and `StrictHostKeyChecking yes`. The explicit known-hosts file may be a read-only passwd-home `known_hosts` if available. Validate the executable and option/config paths as trusted and shell-safe. The agent remains permitted; the config suppresses default identity-file use, proxy commands and local commands subject to local verification. Missing trust or unknown host fails closed. No automatic host-key acceptance. Verify the exact OpenSSH behavior locally, including user config and identity suppression; real authentication remains manual-pending. This is a proposed implementation of E2/E3, not an inherited `GIT_SSH_COMMAND` exception. If fixed safe command construction or known-hosts isolation cannot be established, refuse SSH and seek a decision before implementation. Never permit repository `core.sshCommand`, `ssh.variant`, proxy commands or URL rewrites to influence a connection.

Timeout wrapper must establish a process group, send TERM then KILL after bounded grace, drain/reap and report timeout; verify the actual arrangement of Rust `process_group(0)` and GNU timeout, including a hanging grandchild. Descendants that call `setsid`, same-user interference, uninterruptible kernel waits and process races are outside this guarantee; P06 remains necessary. Never describe process groups as a sandbox.

## Repository trust boundary and procedure

Before any Git command in an existing checkout, hold `.app.lock` and the nonblocking `checkouts/.locks/<repo-id>.lock` through checks, fetch, checkout and state/provenance write. Validate UUID-derived path beneath app-owned checkouts; reject symlinked path components, `.git` indirection/worktrees, alternates, mount escapes and unexpected ownership/type. Avoid check-then-follow races using directory-relative no-follow operations where available; if unavailable, state same-user race limitation and refuse unsafe layouts. External actors are not constrained by the lock. Verify current remote exactly equals the previously validated authorised URL, and do not use repository `origin` as an authority for network connections.

Local Git configuration can execute code or redirect network before a command-line override helps. Before any repository-context Git call, require `.git/config` to be a bounded, regular non-symlink file and run in a trusted non-repository cwd `git config --file <absolute-config-path> --null --list --no-includes` with the cleared environment. Parse complete NUL-framed key/value entries with bounded bytes/counts; reject malformed entries, duplicates and unknown keys, even identical duplicates. Allow only: `core.repositoryformatversion` = `0` or `1`; `core.filemode` = a valid boolean; `core.bare` = false; `core.logallrefupdates` = true; optional `extensions.objectformat` = `sha1` or `sha256`, consistent with the repository format; `remote.origin.url` exactly equal to the authorised URL; `remote.origin.fetch` exactly `+refs/heads/*:refs/remotes/origin/*`; and `branch.<validated-name>.remote` = `origin` plus `branch.<validated-name>.merge` = the matching `refs/heads/<validated-name>`. Require paired branch entries and reject other branch names. Validate expected required keys and structural consistency; allow an extension only where repository format supports it. In particular reject `include`/`includeIf`, URL rewrites, helpers, SSH/proxy, hook, fsmonitor, filters, external diff/textconv, alternate config paths and submodule config. Also reject replace refs, grafts and alternates that change identity or ancestry. Command-line hardening is defence in depth. Prevent config changes between inspection and use as far as the platform permits and document the same-user race. This is a proposed allowlist; its compatibility and safety are not established until T08 hostile fixtures exercise it.

Clone, only after matching `git_acquire` authorisation and locks: (1) require absent confined destination, trusted empty template and clean app-owned home; (2) `git <prefix> clone --quiet --no-checkout --template=<empty-template> -- <validated-url> <destination>`; any failure stops; (3) validate resulting `.git` layout/config and create `.git/info` safely, write exactly `* -filter\n`, read back and compare bytes; (4) fetch the requested branch, tag or full commit OID into an app-owned temporary ref using the same explicit target-fetch policy described for update, then resolve it to an exact commit OID; refuse unavailable targets; (5) `git <prefix> -C <destination> ls-tree -r -z --name-only <oid>` and `git <prefix> -C <destination> check-attr -z --source=<oid> --stdin filter`, passing the first output as binary stdin: require complete NUL-framed triples in identical order, each attribute `filter` and value `unset`; enforce input/output limits, reject duplicate/missing/extra/malformed fields. Filenames are bytes, never line parsed or displayed. P00 refused zero paths: retain that fail-closed behavior as the conservative P04 default, including a valid empty commit; report a no-path refusal. (6) only then `git <prefix> -C <destination> checkout --quiet --force --detach <oid>` and require resolved `HEAD^{commit}` equals verified oid. Checkout can partially modify files on process/IO failure; report error, never claim atomic rollback. Failed clone remains error and any cleanup requires confined safe deletion.

Update, only after matching `git_update` authorisation and locks: (1) validate layout/config/remote, refuse merge, rebase, cherry-pick, revert and bisect states and unmerged index; (2) `git <prefix> -C <destination> status --porcelain=v1 -z --untracked-files=all` and refuse any output, including ignored-file hazards separately checked before checkout; conservative refusal of all untracked files exceeds the minimum but matches P00; (3) fetch the authorised URL explicitly with `git <prefix> -C <destination> fetch --quiet --no-tags --no-recurse-submodules -- <validated-url> <refspec>` without configured remote refspecs. For a branch, the refspec is exactly `+refs/heads/<validated-name>:refs/pwt/targets/<app-generated-id>`; for a tag, `+refs/tags/<validated-name>:refs/pwt/targets/<app-generated-id>` and peel that temporary ref to a commit. For a pinned commit, request only the validated full OID as the source into the app-owned temporary ref; servers may reject raw OID fetch, in which case refuse. Never interpolate arbitrary revision expressions; never follow redirects to an unapproved destination unless policy validates each hop (otherwise disable redirects). (4) resolve fetched target as commit, prove old HEAD ancestor using `merge-base --is-ancestor <old> <target>` before any worktree move; reject divergence, errors, changed HEAD or unsafe status; (5) re-read exact attribute override and verify target paths as for clone; (6) branch only: `git <prefix> -C <destination> merge --ff-only --no-edit <oid>`; tag and commit remain detached: require the previously persisted pin as an explicit operation input, refuse a missing pin or tag retarget, verify the current HEAD equals that pin, and after equivalent checks make no worktree move when the target is unchanged. Verify HEAD = target and capture provenance only on success. Git's merge may partially change files on IO errors; no rollback promise. Do not stash, reset, clean, resolve or push. Fetch writes objects/refs/FETCH_HEAD even on a later refusal: worktree and HEAD unchanged on pre-move divergence is the P00 demonstrated boundary, not byte-for-byte unchanged `.git`. This is the accepted P00 refusal boundary; report the Git metadata exception explicitly rather than claiming byte-for-byte unchanged `.git`.

All managed checkouts are deliberately detached, including branches; branch refresh advances detached HEAD via the verified fast-forward merge and does not update a local branch ref. Ref resolution: validate full branch/tag names with `git check-ref-format` and strict input grammar; reject leading options, revision syntax and ambiguous names. Resolve only explicit `refs/heads/<name>` or `refs/tags/<name>` to a commit (`^{commit}`), rejecting missing, ambiguous, non-commit tags and invalid/abbreviated OIDs. For default branch, resolve advertised symbolic HEAD to a valid `refs/heads/` name; never guess `main` or silently switch branch. Empty remote, absent/unborn HEAD or nonexistent requested ref returns a fieldless no-target error, no checkout/provenance. Full OIDs must match object format (40 hex SHA-1 or 64 hex SHA-256); obtain and validate `--show-object-format`, never truncate. Record actual commit, ref kind/value, Git version and timestamp only after verified success. For a tag, resolve its initial commit and freeze it in `last_commit_oid`; later refresh refuses a retargeted tag. A commit ref remains pinned to its exact full OID, and an unavailable object is refused. These are conservative proposed E8 semantics with no added schema; a failed provenance write must not silently repin. `GitOid` in `workbench/crates/domain/src/store/values.rs` accepts 40 or 64 lowercase hex characters, and store schema 1.4 `$defs/GitOid` likewise permits both; SHA-256 operation remains untested.

## Safe output and local fixture matrix

Every failure crossing runner/service/CLI/store boundaries is a fieldless enum mapped to fixed safe text; no raw Git/helper stderr, URLs, refs, paths, names, stdout, agent socket or secret-bearing Debug output. No captured bytes in logs or events; bounded internal parsing only. Scrub temporary buffers best effort. Credential helper stdout must remain Git's private protocol, not application diagnostics. Record operational status without treating untrusted text as `SanitisedText` merely by wrapping it.

P04 tests, all synthetic and local, must include potency controls and independently assert marker absence, exit/reason and worktree/HEAD snapshots. Port G01–G15 including failed override creation/readback, removed/weak override, weird whitespace/newline names, required process filter and hook controls. Add:

- Local config plus nested `include`/`includeIf`, helper reset/order, helper output containing seeded secrets, `core.sshCommand`, proxy, `url.*.insteadOf`, fsmonitor, diff/textconv and filter macros: prove positive controls execute/rewrite and hardened path refuses before side effects. Test global helper extraction with includes, multiple/empty entries, malformed files, oversized outputs, cwd repository contamination and scoped credentials.
- Attribute output zero paths, path bytes with spaces/newlines/control/non-UTF8, malformed/short/extra NUL triples, mismatched order and output caps; no checkout on failure. Verify target tree rather than current worktree.
- Dirty tracked/untracked/ignored collision, merge/rebase/cherry-pick/revert/bisect, stale/changed HEAD, diverged history, already-up-to-date and fast-forward; snapshot worktree and HEAD and separately record metadata mutation on refusal/fetch failure.
- SHA-1 and SHA-256, default symbolic HEAD, missing/unborn branch, empty repository and empty commit, annotated/lightweight tags, retargeted tag, pinned commit unavailable, invalid/ref-option injection, ambiguous/malformed OIDs and provenance equality.
- Hostile symlink `.git`/checkout/lock/attributes components, linked worktree, alternates, outside symlinks, concurrent lock contention and replacement races; prove no outside modification. Test content symlinks are never followed during deletion.
- Exact child env and seeded-key sweeps over output/events/store, unsupported transports and redirects, no prompts, fake SSH config/agent canaries, bounded stdout/stderr floods, timeout and helper grandchild kill, and an escaping-session control that demonstrates the stated limitation. Test static release feature isolation.

The lead adopts the conservative direct-file helper and pinned-tag choices as proposals within this request, subject to owner acceptance and the listed future tests. Owner decisions are needed only if broader helper/include or SSH configuration compatibility, a stronger metadata-unchanged promise, or support for empty trees is required; those would change the documented boundaries rather than follow automatically from this draft. The app-authored SSH command and trusted known-hosts approach still require local proof before adoption. T01 performs no network and does not establish the P04 test outcomes.
