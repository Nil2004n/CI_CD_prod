## Behaviour to implement
**O3: open hardening in `RealFs`** (all with `std::os::unix::fs::OpenOptionsExt::custom_flags`, std `File::metadata` = `fstat` on the open handle):
- `read`, `write_all`, `sync_file`, `create_new`, `open_lock_file`: open with `O_NOFOLLOW | O_NONBLOCK`. After opening, if the handle's metadata is not a regular file, fail with `io::ErrorKind::InvalidInput` (fixed, no path in the error) without reading or writing.
- `sync_dir`: open with `O_NOFOLLOW | O_DIRECTORY`.
- A FIFO must never block `read` (O_NONBLOCK on open, then rejected as non-regular).
- **No `nlink` check in `read`/`write_all`/`sync_file`**: the §6.3 protocol legitimately leaves the current file with two links between `LinkPrevious` and `Replace`, and recovery must still read it.
- Lock file only: the opened lock handle must be a regular file with `nlink == 1`; otherwise `acquire` returns `StoreError::PathRejected`.

**O2: ownership and mode** (std only; there is no portable way to get the process uid without `unsafe`, so the **uid of the lock file this process just opened/created** stands for "owned by the process"):
- `FileInfo` gains `pub uid: u32` and `pub nlink: u64` (filled from `MetadataExt`). `LockHandle` gains a method returning the `FileInfo` of the open handle (fstat).
- `DataDir::new`: additionally reject (`PathRejected`) a directory whose `mode & 0o077 != 0`.
- `lock::acquire`, after opening the lock file and **before** taking the lock:
  - lock handle must be regular with `nlink == 1` (O3, above);
  - the data directory's uid (from `symlink_metadata` of `dir.as_path()`) must equal the lock handle's uid;
  - each of `rag/` and `backup/` that exists must be a real directory (not a symlink), `mode & 0o077 == 0`, uid equal to the lock handle's uid;
  - any failure → `PathRejected`; nothing else is created or changed, and the lock is not held after the error.
- Add `pub const PRIVATE_DIR_MODE: u32 = 0o700;` and `pub fn check_private_dir(fs: &dyn FsOps, path: &Path, owner_uid: u32) -> Result<(), StoreError>` in `paths.rs` (used by `acquire` and later by the T10 writer when it creates `rag/`/`backup/`), and `StoreLock::owner_uid(&self) -> u32`.
- Doc comments: state the remaining limitations honestly (path-based operations between `acquire` and later writes; `canonicalize`/`list_dir`/`hard_link`/`rename` are not hardened; the uid proxy).
