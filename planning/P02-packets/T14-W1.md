## Required scenarios (minimum)

1. **ENOSPC / EACCES:** for `init_with` and `recover_with` (reconciliation rewriting `log.json` with an interrupted run), a fault (`StorageFull`, `PermissionDenied`) at **every** `WriteStep` that the operation reaches: outcome `failure.class() == FailureClass::Storage`; `cli::commands::Exit::for_failure` of that class is exit **4** (assert the pair, closing L-T12-2); previously existing files byte-identical; no stray temp left after a following clean `recover`.
2. **Interrupted write:** `Interrupted` at each write step → same guarantees; then a clean `recover` (binary or `recover_with` passthrough) reports and removes the leftover temp.
3. **Read faults:** `validate_with`/`show_with` with a fault at `Read` → `Storage` (exit 4), nothing written.

At the **CLI level** (`cli/tests/p02_failures.rs`, real binary via `env!("CARGO_BIN_EXE_pwt-workbench-cli")`, temp dirs under `std::env::temp_dir()`, mode 0700, removed at end):
4. **Malformed JSON, every root:** for each of the nine root names: empty file, truncated JSON, valid JSON of the wrong `store_type`, a UTF-8 BOM, invalid UTF-8 bytes, deep nesting, an unknown field → `validate` verdict `invalid` with the expected problem layer/code, exit 0; `show` prints problems only; no instance value echoed.
5. **Too large:** a root just over the read bound (64 MiB; use a sparse file via `File::set_len` to avoid writing 64 MiB) → `too_large` problem, exit 0, fast.
6. **Stale lock:** an existing unlocked `.app.lock` (from a previous run) → every store command succeeds; contents of the lock file are not echoed.
7. **Lock held by a second process (L-T12-3):** a real second process holds the lock while the CLI runs → exit 3 for `init`, `validate`, `show`, `recover`; succeeds after release. Suggested: the test re-executes its own test binary (`std::env::current_exe()`) with an argument filter selecting a helper `#[test]` that takes `File::try_lock` and waits on stdin/a marker file; no `sleep`-based races without a bounded timeout.
8. **Leftover temps:** temp files matching the app pattern in the root, `rag/` and `backup/` are removed by `recover`; look-alikes, foreign files, and a symlink named like a temp file are left untouched and not followed.
9. **Same-second reports:** create two reports for the same repository in the same UTC second through `persistence::writer::StoreWriter::write_report` (test code may use `persistence` directly), then run the binary `validate` and `recover` → distinct report names, both manifests recognised, nothing reported as orphan/missing.
