## Behaviour
- **Parsing:** std only (`OsString` → UTF-8 where needed; non-UTF-8 argument → usage error, exit 2, without echoing raw bytes). Unknown command/flag, missing/duplicate `--data-dir`, missing `<root>`, unknown root name → exit 2 with a short usage message on stderr. `help` lists every command; `help <command>` the one.
- **`--data-dir` is mandatory** for store commands; no default path; never read `HOME`/`XDG_*`/cwd/temp (the static check enforces this in `cli`, `application`, `persistence` src).
- **`--version`:** `APP_CONTRACT_VERSION`, `STORE_SCHEMA_VERSION`, `WRAPPER_PROTOCOL_VERSION`, `UI_SCHEMA_VERSION` and the crate version (`env!("CARGO_PKG_VERSION")` is compile-time and allowed).
- **`store init`** (T01-D7): `StoreWriter::init` with the real `SchemaValidator`; creates only the five collection roots; idempotent (already-present roots reported, unchanged).
- **`store validate`:** read-only — no reconciliation, no writes, no temp cleanup. Take the data-dir lock (locked → exit 3), read each root (or `--root K`) through the persistence read/validate path with the real `SchemaValidator`, one `StoreValidated` per root; a missing root is reported as such. Invalid stores still exit 0.
- **`store show <root>`:** read-only as above; on a valid root print the **validated, typed, re-serialised** document (never raw file bytes); on an invalid root print problems only (pointer + code, never instance values) — exit 0.
- **`store recover`:** `StoreWriter::open` (reconciliation per §6.5: interrupted runs, temp cleanup, report/manifest mismatches and malformed roots reported, never repaired) → `StoreReconciled`; with `--restore-previous <root>` → `restore_previous` → `StoreRestored`.
- **Errors:** `StoreError::Locked` → 3; I/O / halted → 4; other typed failures → 5. Messages typed, short, never echo file content or paths beyond what the user passed.
- **Output:** human mode writes text through `SanitisedText`/`RedactedText` (escaping control/bidi characters); `--json` writes one JSON object per line (dev records as above; `EventEnvelope`s if any app events are emitted). Write errors on stdout/stderr (e.g. broken pipe) must not panic.
- **Feature index (`features.rs`, `plan.md` §4.1):** rows of requirement ID (PRD/Tech/FR/D-17), command, scenario test function name, mode (`real`/`mock`/`dev`/`manual-pending` + reason). `features` prints it (human / `--json`). One row per P02 command at least.
