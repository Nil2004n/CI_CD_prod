# P02-T01 appendix A — FR-31 draft classification of plain-string store properties

Status: **draft by Opus for owner review with P02-T01** (FR-31 (1)). Generated by a scratchpad script from `schemas/workbench-store-v1.4.schema.json` (sha256 `909e2a55c315ca07096f9123e6986b637a83b1bcdfc4eb6ff88d9d06daa80e2e`); the script fails if any plain-string property is unclassified or a listed property does not exist. "Plain string" = `type: string` (or nullable / array items of it) without `enum`, `const`, `format`, `pattern` or `$ref`.

Scope: the 57 `$defs` reachable from the ten store roots. The six wrapper-protocol `$defs` (WrapperRequest, WrapperControl, TerminationRecord, StreamRecord, DescendantCleanup, TerminationPolicy) are not reachable from any store root and are classified with the wrapper protocol in P06 (request §2, T01-D2).

Totals: 104 properties — E closed enum 6, N validated newtype 66, R `RedactedText` 26, S `SanitisedText` 6.

Rule of thumb applied: text that can originate from a user, a repository, a scanner/tool or a model → R; text the application composes from its own constants and validated values → S; machine identifiers with a closed syntax → N; identifiers with a closed value list in the domain crate → E. T13 turns this table into code and the completeness test; any reclassification after approval is a lead change recorded in the T13 record.
