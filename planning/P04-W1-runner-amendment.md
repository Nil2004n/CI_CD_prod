# P04 wave 1 — internal Git runner amendment

Owner approved preparing and implementing a reviewed internal amendment on 2026-11-03. This is an implementation design, not evidence that a control works. It amends the runner seam in `P04-T01-request.md`; the Git safety annex remains binding. No store schema or approval contract changes are authorized by this amendment.

`GitInvocation` remains opaque. Its crate-private constructors must describe a closed set of operations rather than accept caller-supplied argv, options, environment, executable or timeout. Each operation fixes its argument layout, input kind, output limit, timeout and acceptable exit statuses. Values derived from remotes, refs, object IDs or paths must be validated types and passed as separate arguments in positions safe for that particular Git subcommand. Do not assume every subcommand supports `--`; test each exact argv. No user-supplied Git options or shell evaluation. Constructors and any test fake must not create a production path for file transport.

The initial operation inventory comprises version probing; direct global credential-helper extraction; local config inspection from a trusted non-repository directory; ref validation; clone and explicit fetch; target and object-format resolution; status, in-progress and ancestry checks; target-tree enumeration and attribute checks; verified checkout or fast-forward; and HEAD verification. Do not expose an operation before its inputs, failure behavior and tests are specified. Operations supporting no-result or negative answers must have typed outcomes: helper extraction exit 1 with empty output means no configured helper, and `merge-base --is-ancestor` exit 1 means not an ancestor. Other nonzero exits, signals, malformed outputs and resource-limit failures fail closed and discard captured output. Raw stderr and secrets never cross the boundary into user-facing diagnostics or persisted events.

The real process runner must only use pinned and validated absolute Git and GNU timeout executables, a verified trusted working-directory policy, a cleared exact child environment and the hardening and credential policy in the annex. It must bound concurrent stdin, stdout and stderr; enforce the specified version and time limits; terminate and reap the process group; and retain the documented setsid/same-user limitations. Until executable/cwd trust, exact environment, safe command construction and their local tests are established, `ProcessGitRunner` remains fail-closed. Fixed SSH remains fail-closed until its app-authored configuration, agent and known-hosts policy is locally verified. A test-only file transport or integration fake requires an independently reviewed release isolation design and release negative controls; no release-enabled Cargo feature is authorized.

Verification for each implemented operation includes exact argv/cwd/environment, invalid input and option injection, expected versus unexpected status and malformed output, no secret-bearing diagnostics, and relevant resource bounds. Process tests require output floods, timeouts and helper-grandchild termination with a potency control; version and trust failures require negative tests. Full hostile-repository, approval-path and security review remain P04 acceptance work, not satisfied by a runner unit test. No live network, real credentials or data are permitted without separate authorization.
