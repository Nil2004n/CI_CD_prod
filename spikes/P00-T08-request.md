# P00-T08 — restricted local PDF renderer: request (documentation only)

Status: **proposal, not approved.** Prepared 2026-10-24 from existing research only:
- P00-T03 rev 2 §2 and `evidence/P00/P00-T03/research.md` rows 23/25;
- P00-T01 protocol §4.5 and fixtures §2.12 FX-PDF-*;
- Tech §21, PRD RES-08, Data §18.14, D-07.

There were no new lookups, downloads, installs, builds or conversions. Feature lists and APIs not already in the research are unknown and are marked *to resolve* (stage A) or *verify* (stage D).

Goal: select the pilot renderer for RES-08, meaning deterministic Markdown → restricted local PDF with an independent export state. P12 implements the selection. The JSON and Markdown exports never depend on PDF success.

## 3. Markdown subset (input = the app's deterministic report Markdown, still treated as untrusted because it carries repository-derived strings)
| Construct | P1 behaviour |
|---|---|
| Headings 1–4, paragraphs, emphasis/strong, inline code, soft/hard breaks, thematic break | Rendered |
| Fenced/indented code blocks | Monospace; long lines wrapped at character boundaries with a visible continuation mark; never clipped |
| Bullet/ordered lists, depth ≤ 3 | Rendered; deeper nesting → `limit_exceeded:list_depth` |
| GFM tables (parser option `ENABLE_TABLES`; a runtime option, not a Cargo feature) | Rendered; column widths from content; cells wrap; header row repeated after page breaks |
| Links / autolinks | Rendered as text `label <url>`; **no link annotation and no `/URI` action** |
| Images | Never loaded; rendered as text `[image omitted: <alt>]` |
| Raw HTML (block/inline), HTML comments | Not interpreted; rendered as escaped literal text with a `[raw HTML not rendered]` marker |
| Footnotes, task lists, strikethrough, math, definition lists | Parser options off; their source text appears literally (documented) |
| Control/bidi-override characters (e.g. U+202E, U+200B, C0/C1) | Made visible as `<U+XXXX>` (display safety, Arch §13); never passed through as layout controls |

W receives HTML generated by the spike from the **same event stream**, with every text node escaped, no raw HTML passthrough, no `<img>`/`<link>`/`<style>` from content, one fixed internal stylesheet, and no scripts. WeasyPrint does not execute JavaScript; this is *verify*: absence is checked in the output.

## 5. Restrictions
- **Remote:** P1 has no fetch code by construction (stage A/B graph check plus a source grep for `std::net` and HTTP clients). Both candidates run inside `unshare -rn` (loopback only). W uses a deny-all `url_fetcher` that records each denied URL scheme and host (no query strings).
- **Local files:** P1 opens only allowlisted font files and the input/output paths passed by the harness. W runs with a private `HOME`/`XDG_*`, a spike-written `fonts.conf` (`FONTCONFIG_FILE`) listing only the allowlisted font directories with a cache under the private `XDG_CACHE_HOME`, and the deny-all `url_fetcher` (`base_url=None`).
- **Active content:** P1 emits no annotations, actions, forms, JavaScript or embedded files. W output is checked by the same object scan.
- **Environment:** `env -i` with only `PATH`, `LANG`, private `HOME`/`XDG_*` (and `FONTCONFIG_FILE` for W). No keys, tokens or session variables.

## 6. Input and resource limits (spike values; production defaults stay a later owner decision, as FR-11)
- Markdown ≤ 8 MiB; nesting ≤ 16; table ≤ 32 columns; cell ≤ 64 KiB; pages ≤ 2,000; output ≤ 64 MiB.
- Per conversion: 60 s wall time; `ulimit -v 2097152` (2 GiB).
- Whole run: outer `timeout -s KILL 900`.
- Exceeding any limit → typed failure; no partial PDF is reported as written.

## 7. Artifact verification and failure behaviour
A conversion counts as successful (`pdf_written=true`, Data §18.14) only after all of these:
1. Output written to a temp file in the output directory, flushed, size > 0 and ≤ limit.
2. The header starts `%PDF-1.`, and `%%EOF` appears in the last 1 KiB.
3. `mutool info` parses it, with a page count within the expected range.
4. `mutool draw -F txt` text extraction contains the fixture's sentinel strings (first and last finding IDs, sampled table cells) and, outside C1, no canary.
5. A forbidden-object scan of `mutool clean -d` output (decompressed) is clean.
6. Rename to the final name; record SHA-256, renderer ID/version and page count.

On any failure: remove the temp file, set `pdf_written=false` and record a typed error (`font_unavailable`, `limit_exceeded:*`, `render_error`, `verification_failed:<check>`, `write_failed`). The JSON and Markdown exports are untouched, and regeneration without rescanning stays possible (RES-08).
